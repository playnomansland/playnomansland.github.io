# Online: live matches, server, lobby, friends, history, tournaments

Moved out of the README on 2026-11-11 so sessions only read the part they need; the text is unchanged.

## How live matches work

- **On the game server (since 2026-11-02, server step 3):** friends' matches on the built-in units and tournament matches are refereed by the game server (`server/src/room.js`, one Durable Object per match code, WebSocket `/room/<CODE>`; a tournament match is `/room/<CODE>?t=<TOURNAMENT>`). Both phones are equal players (`mode = 'net'`, `me` = the side the server gives: the one who made the match, or a tournament match's host, is side 0). Links are `?play=CODE`.
- **Actions, not state:** every Game call a player makes on their own side that works (`Referee.ACTIONS` in `src/referee.js`: place, move, sell, level, skill, unlock, package and tower picks, loan, slot spin, walls, Mark, and the rest) is also sent as `{ t: 'act', seq, fn, a }` (the wrapper after `SFX_ACTS`, `srvAct`). The server runs the same Game function on its own match for that side (`Referee.act`: only listed functions, only the listed argument kinds, only while deploying and not Ready), so a modified page can only do what the rules allow. Each action is acked with the server's fingerprint of that side (`Referee.sideHash`); a phone out of step asks for a sync. A phone plays its actions at once on its own copy and keeps them as pending until acked; a view from the server replaces the copy and the pending ones are played again on top (`srvReplay`). Undo all is an action too (`undoAll`: back to the same point as on the phone, `Referee.sideState` / `restoreSide`, which the page uses as well).
- **Hidden info is kept on the server:** each phone (and each spectator) only gets its view (`Referee.view` / `hide`): the opponent's squads, levels, skills, sales, moves, unlocks, walls, Mark, tower buys and picks of this round, their gold and extra deployment as the round began, and in round 1 their leader, packages, buff tiles and spins. The fight (`{ pre, post, summary }`, `Referee.fight`) shows everything, as before.
- **Clock and flow on the server:** the deploy clock (90 s, or the tournament's) is a Durable Object alarm; it waits for tower picks, the leader draft (each pick has `Referee.DRAFT_PICK_MS`, 20 s, then `draftClock` picks the first leader left) and for a player who is away (up to 2 minutes, `AWAY_MAX_MS`), and the fight starts 0.5 s after it runs out (`GRACE_MS`). Ready, next round (a player who is away moves on by themselves) and rematch go through the server. A reloaded phone gets its side back with its key (`phonebellum.net.v1`, the ?play= link or Back to match on the menu). A tournament match starts by itself once both players are in and the server sends the result to the tournament (`TourRoom.serverResult`); phones don't report it.
- **Pick clock (2026-11-10):** the round 2 leader pick and the round 3 tower pick count down on the pick screen (`#pick-clock`: big seconds and a bar that runs down; red and pulsing for the last 10 s; the Hide button's label carries the seconds too). 20 s a pick (`Referee.TOWER_PICK_MS`, and `DRAFT_PICK_MS` for each leader pick, whoever's turn it is). On the server `towerClock` (beside `draftClock` in `src/referee.js`) gives a player who hasn't picked in time the first tower on offer, and `sync` / `status` carry `pick` (ms left, `Referee.pickLeft`); the page sends the card its player tapped just before. Vs the computer and phone to phone each page runs its own player's clock (`pickTick` in `src/site-template.html`) and picks the tapped card, or else the first leader left / the first tower. No pick clock where there's no deploy clock (vs the computer with the timer off, the tutorial, puzzles) or in 2v2. The deploy clock still waits for the picks, so pick time never eats deploy time. Checks: `node tools/tests/referee.js` (clock section).
- **Phone to phone (PeerJS), the fallback:** Factions matches, Counter Lab units, `?peer=1`, old `?join=` links, the lobby's Phone to phone instead button, a typed code nobody made on the server (`nomatch`), and a new match when the server can't be reached at all. A tournament goes phone to phone when its `net` setting is `peer`. Phones then connect over WebRTC using [PeerJS](https://peerjs.com) and its free public matchmaking server; the host's phone runs the match and trusts what the guest sends. The host's match is saved on the host's device.
- The battle engine only uses arithmetic that gives identical results in every browser (and on the server), so both phones play back the same fight.
- Each round has a deploy countdown of 90 seconds. The fight starts when it runs out, or earlier when both players tap Ready.
- Tests: `node tools/tests/referee.js` (headless: whole matches on every map with every leader, phones and server in step, playback the same, cheating refused, the clock), `cd server && npm test` (the same over WebSockets against the local server, reconnects, tournament results), `node tools/tests/server-match-ui.js` (two pages in the browser), `node tools/tests/server-history-ui.js` (match history from the server), `node tools/tests/account-ui.js` (the Account sheet), `node tools/tests/prepare-units.js` (the server's units are the page's).
- **Starting units (2026-11-07):** in round 1 each player sees which units the opponent's package squads are (`Game.startSeen(m, side)`: the package's `squads`, or `m.packSeen[side]` where the screen doesn't have the package), never where they stand, the leader or the package itself. The server's view (`Referee.hide`) and the PeerJS guest's (`syncState`, plus `start` on the host's `status`, sent when it picks) carry `m.packSeen` (`UNDO_SKIP`, so `sideHash` is unchanged). The page lays them out (`foeStart()` in `boardView`: `[{ unit, x, y }]`, side by side along the back row of their zone, away from their tower; not in 2v2, tutorial, sandbox or for spectators) and both boards draw them see-through with a label (render2d `drawFoeStart`, render3d `collectDeploy` with look `ghost` and a `label|` sprite). Check: `node tools/tests/start-units-ui.js` (AI, and a PeerJS match when the peer server is up).
- **The AI presses Ready (2026-11-07):** against the AI (mode `ai`) there is no Fight / Fight now button: the player has the online Ready / Not ready button (`fightBtn()` is false only there; tutorial, puzzles, Replay a round and Claude keep Fight). `aiReadyTick` (from `tick`) sets `ready[1]` `AI_READY_MS` (5000) after the player can deploy: the count restarts while a package, tower or leader pick is open or the AI waits on the player's leader pick (`aiWaits`), unless the player is already ready. Both ready (`toggleReady` or `aiReadyTick`) runs the fight; the clock still ends the deploy as before. `boardView().foeReady` and `dragonCheck` follow `ready[foe()]` there, so the looks' opponent-ready scenery (Forest Glade explorer, Savanna vultures, Ashlands dragon) plays against the AI. Under `?test` the AI is ready at once unless `?aiready=ms`, so the UI tests click `#ready` where they clicked `#fight`. Check: `node tools/tests/ai-ready-ui.js`.
- **Fight speed:** both phones play a fight at the same speed. A player's pick (1×, 1.5×, 2×) is what they want, and the fight plays at the slower of the two picks: a faster pick is a request ("Opponent wants 2×", that button glowing on the other phone) that takes hold on both once the other picks it too; a slower pick slows both at once. Picks carry over to the next fights of the match; a new match starts at 1×. Against the computer the buttons just set the speed. (`liveSpeed`, `playSpeed`, `showSpeed` in `src/site-template.html`.)
- **Switching away mid-fight** (another tab or app) pauses the replay where it is; coming back goes on from there. In a live match the other player waits on the results screen meanwhile (the next round needs both), so after 45 s away (`LIVE_AWAY`) the rest of the fight plays out to its result, as before. `tools/tests/playback-mp.js` checks both.
- **Fair turns:** the engine gives neither side the edge in a tie. The side whose bodies act first alternates every tick; both sides move from where everyone stood when the tick began; a body killed this tick still attacks; heals, lifesteal, Glut, range cuts, knockback, stealth reveals and a fallen tower's penalty take hold once the tick's attacks have landed; side 1's squads stand mirrored (front row first); each side draws dodges and random heals from its own stream. Mirrored armies come out as exact mirrors (`node tools/tests/fairness.js`); before, the host won about 60% of mirrored duels that weren't draws.

## Game server

Online play runs on our own server (Cloudflare Workers + Durable Objects) in `server/`: tournaments (step 2), the referee of live matches (step 3) match history (step 4: every round of every server match, `server/src/history.js`, read with `GET /history`) and accounts (step 5: guests and Sign in with Google, `server/src/accounts.js`, a D1 database; switched off until the database is bound). Plan, security and accounts: [docs/SERVER.md](SERVER.md). Games played per day (2026-11-10, counts only, by kind: vs the computer, phone to phone, online, puzzles): `GET /games?days=7` on the game server ([docs/SERVER.md](SERVER.md) "Games played per day"). Local: `cd server && npm i && npm run dev`; test: `npm test`.

## Online lobby, chat and emotes (2026-11-04)

PLAY → **Online · Rooms** opens the lobby (`home.screen = 'lobby'`, `drawLobbyScreen` in `src/site-template.html`): one **Rooms** list of every public room, Standard and Ranked together (2v2 only for developers while the server's config key `lobby_duo` is `'dev'`). **Sort** (Name, Date/time (default, newest first), Category, Mode; the active one again flips it; `pb-lobby-sort`), **Quick play** (the oldest open public Standard room, or a new one), **Create room** (Mode, Public / Private, Spectators on / off; map, look and leaders are picked in the waiting room as before), **Join** / **Watch** on each card, and join by code. Cards show the host's nameplate, the room name, tags, map, players, round and watchers. One WebSocket to `/lobby` while the screen is open (`lobbyOpen / lobbyRecv / lobbyDraw`); it closes when a match starts. After a match from the lobby, Main menu goes back to Rooms.

- Server: `LobbyRoom` (`server/src/lobby.js`, one instance `all`) keeps the listings; `Room` and `DuoRoom` report their own card on every change and every 60 s while public (DO RPC `upsert` / `drop`), and the lobby drops a card not heard from for 3 minutes. Joining and watching are the existing room messages, so match play is unchanged. A public waiting room lets a new player take side 1 if the one who had it left before the start. Spectating is on by default; the host can turn it off in the waiting room or in Settings during the match.
- **One room once (2026-11-04):** the account that has side 0 is refused side 1 of the same room (`denied { why: 'here' }`, the page says "You're already in that room"), from another phone, another tab, the list or the code; its own phone still comes back to its own side with its key, and a ranked room keeps its own `'self'` for the same thing. Quick play never hands a player the room they host either (`LobbyRoom.quick` leaves out the asking account's own listing).
- **Rooms close when nobody is in them (2026-11-04):** `EMPTY_MS` (a minute) after the last phone leaves, a room with no match running takes its card off the list, deletes its storage and forgets its keys, so the code answers `nomatch`. A match that has started is never closed that way: it plays on without the players (`Ref.AWAY_MAX_MS`) and ends by itself, and the room closes once it has. `ROOM_EMPTY_MS` makes the wait short in tests. The same in `DuoRoom`.
- **Chat and emotes** (server matches only, not PeerJS): the talk button (in the tray row while deploying, on the board otherwise) opens the wheel with the three emotes (Flame Wizard *BABABABA*, a happy Ether Golem, a shell-shocked Sniper; `img/emotes/*.svg`, drawn from the 3D models; no sounds) and a chat line. Text chat is for phones signed in with Google; guest accounts read chat and send emotes. Lines pop up under the HUD for a few seconds and are all in the Chat sheet; the badge on the talk button counts only lines that came in, never your own, which the room echoes back to you (`lineMine`). Emotes show ~1.5 s by the sender's nameplate and over their side of the board (CSS pop / shake / bounce / twitch). The opponent's nameplate: Mute emotes, Mute chat (per match code, `pb-mute-<code>`), Report (the room's own last 20 lines to a moderators' Discord channel). Spectators chat among themselves while the match runs; when it ends the players get those lines and the chats are one until a rematch starts. 2v2: a Team / All switch. Settings: Chat and Emotes on / off (`snd.chatOn`, `snd.emotesOn`).
- Plan: [docs/LOBBY.md](LOBBY.md); server side: [docs/SERVER.md](SERVER.md) "Online lobby". Not built yet: the ranked queue, a block list, lobby-wide chat.
- Checks: `server/test/lobby.test.js` and the chat part of `server/test/match.test.js` (in `npm test`), `node tools/tests/lobby-ui.js` and `node tools/tests/chat-ui.js` (browser; need `python3 -m http.server 8766`, start their own servers on 8781 and 8782).

## Friends (2026-11-04)

Signed-in (Google) players have a **Friends** button (main menu top bar, and the in-match Settings): a Friends sheet with tabs Friends and Requests and an *Add by username* box. Each friend row has a green (online) or grey (offline) dot with *Online*, *In a room*, *In a match · round N* or *Last seen*, and **Invite** (online friends only: makes a private room the normal way, then sends the invite), **Message** (a thread sheet) and ⋯ (Remove friend, Mute messages). The friend gets an invite banner (Join = the normal join of the room's code) outside matches, only the badge during one. Tapping the opponent's name in a match or a leaderboard row gives Add friend / Message. The page keeps one socket to the player's own `PlayerHub` (`server/src/hub.js`) while it is open and sends where it is (menu, room, match) every time that changes; the lists come from `/account/friends`. Code: the "friends" block in `src/site-template.html` (`fr`, `hubOpen`, `hubRecv`, `hubSend`, `frTick`, `openFriends`, `frThread`). Server side, tables and limits: [docs/SERVER.md](SERVER.md) "Friends". Checks: `server/test/friends.test.js`, `server/test/hub.test.js` (both in `npm test`), `node tools/tests/friends-ui.js` (two browsers; needs `python3 -m http.server 8766`).

## Report a bug (2026-11-04)

Settings (the cog in a match, or the menu's Settings) has **Report a bug**. The player writes what happened; the page adds the game version (`GAME_VERSION`, stamped by `src/build.js`: the newest PATCH-NOTES date and a hash of the page), the match id (for server matches the same `<room>-<seed>` id as match history; `ai-<seed>`, `peer-<code>-<seed>` otherwise), round, phase, map, 2D/3D, device and username. The server (`POST /account/bug`) makes a new post in the Discord forum #bug-reports through a webhook, titled by the first line, and the sheet links to it so screenshots can be added. If posting is off or fails, the whole report is copied and the sheet offers Open Discord instead. Setup: a webhook on the #bug-reports forum, saved as the GitHub secret `DISCORD_BUG_WEBHOOK` (the server deploy copies it to the Cloudflare secret `BUG_WEBHOOK`). Details: [docs/SERVER.md](SERVER.md) "Bug reports". Checks: `server/test/bugs.test.js`, `node tools/tests/bug-ui.js`.

## GG, Replay a round and match history (2026-11-04)

- **GG:** after an online (server) match the match-over card has **Say GG**; the other phone shows "<name> said GG". Between two accounts it counts towards the other's **Good sport** title (10 GGs, at most 3 from the same player, only finished matches with 3+ fights). Page: `ggRow`, `sendGG`, `ggGot`; server: room.js `gg`, accounts.js `GG`. The Rewards sheet shows the count.
- **Replay a round:** the match-over card's **Replay a round** (in place of Look at board; 2v2 and spectators keep Look at board) lists the rounds played. A round starts again from its start: your side as it was once that round's picks were done (the Undo all point) and the opponent's army as it fought, in plain sight. Deploy, Fight, see how it goes; **Try again**, **Other round** or **Back to results**. Played in mode `sandbox` on a copy (no clock, no AI, nothing saved or sent); an online opponent's messages wait meanwhile (`sbxHold`). The log (`roundLog`) is per match on this phone and is lost on a reload. Test: `node tools/tests/replay-round-ui.js`.
- **Match history:** Profile → Match history opens on **My matches** (signed in, guests included): one card per online match with the opponent's username, the result, rounds, health, damage, map and leaders, and every round with its armies and a **Replay** (mode `replay`: plays the saved fight, then back to the history). `histFriendBtn(tag)` is where the friends system adds an Add friend button. The old lists stay as **All online** and **Phone-to-phone**.
- **While replaying (2026-11-07):** `sbxHold` calls `sbxPeek` on every held message (it still waits in `sbx.inbox`). The opponent's rematch / next game (status or sync `rematch[foe]`, the host's `{t:'rematch'}`) or GG goes through `sbxNote`: a banner, `sfx('menu')` and a line in `sbx.notes` (`sbxNotesHtml`, next to `#sbx-back` and on the `sbxResult` card). On `sbxNewGame` (a fight, a draft, or a sync in phase 'deploy') `sbxHold` calls `sbxExit()` first, then shows 'The next game has started'. `replayBtn` returns Look at board once `rematch[me]` is set online.
- **GG delivery (2026-11-07):** `sendGG` sets `net.ggPending` (the button reads 'Sending…') until the echo in `ggGot` or a sync's `net.gg` confirms it; a sync resends `{t:'gg'}` only if it is still pending and the server's `gg[me]` is false. `ggAnnounce(seed)` shows the banner and sound once per match (`net.ggShown`). Server: room.js `gg` calls `hubEvent(env, pid, { t: 'gg', from })` (now exported from accounts.js) when the receiver has no open socket; the page's `hubRecv` shows a toast (Google accounts only). Tests: `server/test/gg.test.js`, `tools/tests/gg-history-ui.js`.

## Leader draft (2026-11-05)

- Packages no longer carry a leader (`p.char` is null). `createMatch` makes `m.draft = { pool }`: `Game.DRAFT.pool` (5) leaders, seeded, from the match's leaders (`offChars` out; always at least 2). Off for Factions, the devtest, 2v2 (`noChars`), the tutorial and puzzles (`opts.draft === false`).
- Before round `Game.DRAFT.round` (2) both pick from the same pool: `draftFirst(m)` is round 1's winner (a draw: a coin flip from the seed); `leaderTurn` lets the second player pick once the first has; `pickLeader` refuses a taken leader. Picks are open (`hide` only hides leaders in round 1). `settleLeaders` (called from `ensurePack`, so before every fight) picks the first leader left for anyone who didn't.
- Server: `pickLeader` is a referee action; the clock waits for the draft; `draftClock` gives each pick 20 s (30 s before 2026-11-10). Page: a `leader` kind in `pickOptions` (cards `data-leader`); vs the AI, an AI that picks second deploys after the player's pick (`aiWaits`, `foeLeaderTurn`); phone to phone, the guest sends `leader` and the host's `applySide` takes it only in turn.
- Text (2026-11-07, rule unchanged): `draftStakes()` adds 'Win this round: you pick your leader first in round 2.' to the round 1 package card, `draftFirstLine(sum)` the round 1 result card's line (`p.draft-first`: win, loss, timeout = more health left, draw = coin flip), and the leader sheet uses the timeout wording when `m.history[0].timeout`. Only when `Game.drafting(m)`.
- Tests: `node tools/tests/leader-draft.js` (headless), `node tools/tests/leader-draft-ui.js` (browser, port 8766).

## Referee hardening (2026-11-05)

From `docs/EXPLOITS-2026-11.md`: `mark`, `loanT`, `pack` and `vote` are in `UNDO_NULL` (Undo all no longer makes the Mark free); `Referee.act` refuses an action whose `seq` isn't above the last one handled (`why: 'dup'`); a loan keeps the terms it was taken on (`m.loanT`, `Game.loanTaken`); argument kind `i` is 0 or more (offsets are kind `d`, used by `setAim`). Each carrier lets one earlier-round squad out and one in per round (`m.horse`, `horseOk`, hidden from the opponent while deploying). Test: `node tools/tests/referee-fixes.js`, `node tools/tests/horse-out.js`.

## Tournaments (invite only)

- **Start screen → Host a tournament.** The game server keeps the tournament (`server/src/tour.js`, one Durable Object per tournament code, WebSocket `/tour/<CODE>`; the rules are `src/tournament.js`, global `Tour`, which runs in node and on the server). The organizer's phone gets a secret key when creating it and sends organizer actions as `{ t: 'org', op, a }` (`tourDo` → `Tour.apply` on the server); each player gets their own key on joining (ids are public, keys never are). The tournament goes on when the organizer's phone closes. Players join with `?tour=CODE` or the 4-letter code; `?tour=CODE&watch=1` is the big-screen view. `?server=URL` points the page at another game server (tests use a local one).
- **Formats:** Swiss + playoffs (Auto: 2 rounds up to 4 players, 3 up to 8, then 4; playoffs Auto top 4 from 5 players, top 8 from 14) or Knockout (seeded at random, byes to the top seeds). Swiss pairs players on the same score, never the same pair twice where possible, the bye to the lowest without one (counts as a win). Standings: points (win 1, draw ½), then Buchholz (opponents' points), then health difference. A playoff draw must be replayed or settled by the organizer.
- **Matches:** the hub gives every match a 5-character match code and a host (players take turns hosting; the host is side 0). Both tap Start match / Join match and the game server starts it once both are in (`srvJoin` with the tournament code; the server checks each player's tournament key with `TourRoom.matchFor`). With the `net` setting on `peer` the host's phone runs it over PeerJS instead (`drawTourLobby` starts it by itself). A tournament match is made by `tourCreateMatch`: built-in units, the tournament's map (fixed, or one random map per round, the same in every match of it), look, unit pack, leaders and units left out, `packOptions` leader choices and `mirror` (both players get the same package options, tower offer and Zoe tiles: `opts.mirror` / `opts.packOptions` in `Game.createMatch`). Timers come from the tournament (`deployMs`, `nextSecs` via `tourSet`). The HUD shows the opponent's username.
- **Results** of server matches come from the server (`TourRoom.serverResult`); the tournament ignores phones' reports for them. Phone-to-phone matches (`net: 'peer'`) are reported by both phones when the match ends (end screen, forfeits too; `tourReport`, resent after a reconnect). The organizer's result always counts and can be changed; two phones that disagree mark the match. The organizer can also replay a match (new code), swap its host, drop a player, undo a round's pairings and rename anyone.
- **Bots** (practice): Practice vs bots on the start screen = you + 7 bots (`tourPractice`); Add a bot in any lobby (`Tour.addBot`, players with `bot: true`). Bot against bot is played out on the server by the AI on both sides (`simBotMatch`, one match per alarm). A person against a bot plays an AI match on their own phone with the tournament's settings (`tourPlay`, `tour.botMatch`; `tourLive` covers it) and reports it like any other. Test: `node tools/tests/tournament-bots.js`.
- **Best of N** (`settings.bestOf` 1/3/5/7, playoff matches only): a series match has `bo`, `games` and `codeGame` (each game's own match code → game number). Phones report `{ match, game }`; a game already in is only compared (conflict if different), a drawn game doesn't count, the series ends at `Tour.winsNeeded`; until then `nextCode` gives the next game a code. Organizer: add a game, `Tour.undoGame`, `Tour.replay` (restarts the series).
- **Changing pairings:** `Tour.swapSlots(t, s1, s2)` trades two slots of the current round (`{ m: matchId, k: 'a' | 'b' }`, or `{ p: playerId }` for an active player not in the round, e.g. outside the playoff cut). Only matches with no result and no games (`Tour.editable`); a bye stays (player, empty); changed matches get new codes (a series starts over). UI: Matches → Change pairings (`tour.edit`, `tour.editSel`, `data-slot`). Phones send the match code with each result and the hub ignores a game whose code no longer counts; a phone mid-game on a moved match shows Match moved (`tourMoved`). Test: `node tools/tests/tournament-pairings.js`.
- **Bracket:** `tourBracketData` (all rounds: played, to come with TBD, champion; projected from the standings before the playoffs) and `tourBracketSvg` (SVG with connectors; `big` for the big screen). Bracket tab, a Bracket button (sheet), shown by itself to players between playoff rounds (`tour.autoTab`). The big screen (`?watch=1`, class `tourtv` on `<html>`) hides the board and shows the bracket full width.
- **Spectating:** on a server match, Watch connects to the match room as a watcher (`srvJoin` with `watch`): it gets the spectator view (neither side's new things while they deploy) and every fight. On a phone-to-phone match, Watch connects to the host's match peer with `metadata: { spec: true }`; the host keeps spectators in `net.specs` apart from the guest and sends them `specState()` (the guest's view minus the guest's own squads, skills, leader and tower pick of this round) on every sync, and every fight in full. The client runs `mode = 'spec'` (`specRecv`, `specApply`, `specResult`): no controls (`editable`, `tick`, `runFight` skip it), host at the bottom with both usernames in the HUD. Test: `node tools/tests/tournament-series.js`.
- **Saved:** the organizer's key in `phonebellum.tour.org.v2`, a player's in `phonebellum.tour.me.v2` (`{ code, id, key, ts }`); both reconnect by themselves. The tournament itself lives on the server and is deleted when ended or after 14 days untouched.
- Tests: `node tools/tests/tournament.js` (pairings, standings, playoffs, mirror rolls), `cd server && npm test` (the server's tournament rules: keys, organizer rights, results, bots), `node tools/tests/tournament-ui.js` and the other tournament-*.js (organizer and phones through whole tournaments; need the local page server, peer server and `cd server && npx wrangler dev --port 8798`).
